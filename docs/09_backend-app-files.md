# ไฟล์ใน x-fitness/backend/app/ ทำอะไรบ้าง

สรุปหน้าที่ของแต่ละไฟล์ในโฟลเดอร์ `app/` ของ backend (FastAPI) · ตรวจกับโค้ดจริงเมื่อ 25 ต.ค. 2569 · ทั้งโฟลเดอร์มีโค้ด Python 17 ไฟล์ และ prompt 3 ไฟล์

## ภาพรวม

```text
ลูกค้าเว็บ ──► chat.py ──┐
ลูกค้า LINE ─► line.py ──┤
                         ▼
          chat.answer(): guard.py ขาเข้า → rag.py ค้นคลังความรู้ → business.py กฎร้าน + ข้อมูลสมาชิก
                         → llm.py เรียก Typhoon → guard.py ขาออก → คำตอบ
          chat.read_image(): llm.py (typhoon-ocr อ่านภาพ) → llm.py (Typhoon จัดเป็น JSON) → business.check_slip

พนักงาน ──► conversations.py (กล่องแชต) · backoffice.py (ชำระ จอง โปร สมาชิก) · knowledge.py · dbviewer.py
                         ทุกไฟล์อ่าน/เขียนผ่าน db.py → ฐานข้อมูล SQLite ไฟล์เดียว
```

## รายละเอียดทีละไฟล์

### main.py
จุดเริ่มของแอป (`uvicorn app.main:app`) · รวม router ของทุกไฟล์ · เสิร์ฟหน้าเว็บจาก `frontend/` และเอกสารจาก `documents/` · มี `GET /api/health` บอกโมเดลที่ใช้ ตัวค้นคลังความรู้ (LightRAG หรือคำสำคัญ) และว่าตั้ง key ของ Typhoon กับ LINE แล้วหรือยัง · ตอนเปิดแอปจะเตรียมฐานข้อมูล แล้วสร้างดัชนีคลังความรู้ส่วนที่เปลี่ยนไว้เบื้องหลัง ไม่ทำให้แอปเปิดช้า

### config.py
ค่าตั้งทุกตัวอยู่ที่นี่ที่เดียว อ่านจาก environment variable หรือไฟล์ `backend/.env` เช่น `TYPHOON_API_KEY` · ชื่อโมเดล (`CHAT_MODEL` = typhoon-v2.5-30b-a3b-instruct, `VISION_MODEL` = typhoon-ocr) · ค่าของ LINE · บัญชีหลังบ้าน · ที่อยู่ไฟล์ฐานข้อมูล · ขีดจำกัดจำนวนข้อความ · ค่าตั้งต้นพร้อมใช้สาธิตในเครื่อง

### chat.py
ตัวบอท ใช้ร่วมกันทั้งหน้าเว็บและ LINE
- `POST /api/chat` รับข้อความ → `answer()`: guard ขาเข้า → ยืนยันสมาชิก → LightRAG ค้นความรู้ → แนบกฎร้านและข้อมูลสมาชิก → Typhoon ตอบ → guard ขาออก
- `POST /api/vision` รับภาพ PNG/JPG ไม่เกิน 5 MB → `read_image()` อ่านภาพ 2 ขั้น (ดูหัวข้อ prompts)
- `verify_step()` ยืนยันสมาชิกที่พิมพ์มาในแชต (รหัสสมาชิก + เบอร์ 4 ตัวท้าย) · `verified()` นับครั้งที่เดาผิดร่วมกับ `limits.py`
- `body_scan_reply()` สรุปผลวัดร่างกายโดยไม่ตัดสินว่าค่าดีหรือไม่ดี (กฎ N-06)
- `history()` ดึงข้อความก่อนหน้าในแชตเดียวกันมาให้ AI อ่านต่อ

### guard.py
ด่านตรวจที่เขียนเป็นโค้ด ไม่พึ่ง system prompt อย่างเดียว
- `check_input()` ขาเข้า: ข้อความอันตราย (14 หมวดของ Llama Guard 3) · ขอข้อมูลสมาชิกคนอื่น · หลอกให้เผย prompt ฯลฯ → ตอบด้วยข้อความตายตัวทันที ไม่เรียก AI
- `check_output()` ขาออก: ตัวเลขราคา เวลา หรือลิงก์ที่ไม่มีในคลังความรู้ · คำตอบที่ลอก system prompt ออกมา → แก้หรือแทนคำตอบ
- ข้อความตายตัวอ่านจาก `data/guard/replies.md` · รหัสกฎ (N-xx, D-xx) ตรงกับ `docs/03_bot-rules.md`

### rag.py
ค้นคลังความรู้ `data/knowledge-base/*.md` ด้วย LightRAG (กราฟความรู้ + ค้นแบบเวกเตอร์)
- ตอนสร้างดัชนี ใช้ Typhoon ดึงสิ่งที่พูดถึงและความสัมพันธ์จากแต่ละไฟล์ ทำครั้งเดียว · เวกเตอร์ทำด้วย `hash_embed()` ในเครื่อง ไม่ใช้โมเดล
- ดัชนีเก็บที่ `data/rag-index/` · สร้างใหม่เฉพาะไฟล์ที่เนื้อหาเปลี่ยน (ดูจาก `manifest.json`)
- `context()` ส่งความรู้ที่เกี่ยวข้องและรหัสเอกสารให้ `chat.py` · `search()` ใช้ในหน้าทดสอบค้นของหลังบ้าน
- ไม่มี `TYPHOON_API_KEY` → ใช้ `keyword_search.py` แทน

### keyword_search.py
ทางสำรองของ `rag.py` · ตัดคลังความรู้ตามหัวข้อ `##` แล้วค้นแบบ TF-IDF ด้วยตัวอักษรติดกัน 2–3 ตัว ใช้กับภาษาไทยได้โดยไม่ต้องตัดคำ ไม่ต้องใช้ API

### business.py
ข้อมูลร้านจากฐานข้อมูล และการตรวจที่ต้องทำด้วยโค้ดเพราะ AI เคยตอบผิด
- `table()` อ่านตารางข้อมูลร้านทุกครั้งที่ถาม พนักงานปิดโปรในหลังบ้านแล้ว บอทรู้ทันทีในข้อความถัดไป
- `verify()` ตรวจรหัสสมาชิกกับเบอร์ 4 ตัวท้าย · `member_context()` ข้อมูลที่บอกสมาชิกที่ยืนยันแล้วได้ (ไม่มีเบอร์โทร)
- `rules_for()` แนบข้อเท็จจริงที่คำนวณด้วยโค้ด เช่น เวลาเปิดรายวัน ความคุ้มของรายปี โปรใช้กับแพ็กเกจไหน ตารางคลาส
- `check_slip()` ตรวจสลิป 5 ข้อ (ชื่อบัญชี เลขบัญชี ยอด วันที่ เลขอ้างอิงไม่ซ้ำ) · ผลเป็นการตรวจเบื้องต้น พนักงานเท่านั้นที่กด "ชำระแล้ว" ได้

### llm.py
ส่งคำขอไป Typhoon ด้วย httpx ไม่ใช้ SDK · `chat()` สำหรับแชต · `vision()` ส่งภาพแบบ base64 ให้โมเดลอ่านภาพ · ผิดพลาดแล้วโยน `LLMError`

### prompts/
| ไฟล์ | ใช้ตอน | โมเดล |
|---|---|---|
| `system.md` | ทุกข้อความแชต: บทบาท "เอ็กซ์" สิ่งที่ต้องทำและห้ามทำ ใส่วันที่วันนี้ให้ | Typhoon แชต |
| `ocr.md` | อ่านภาพขั้นที่ 1: อ่านตัวหนังสือในภาพทุกตัว ตอบเป็นข้อความธรรมดา | typhoon-ocr |
| `vision.md` | อ่านภาพขั้นที่ 2: เอาข้อความจากขั้น 1 มาจัดเป็น JSON (สลิป ผลวัดร่างกาย ใบเสร็จ โปสเตอร์ อื่น ๆ) | Typhoon แชต (ไม่เห็นภาพ) |

แยก 2 ขั้นเพราะ typhoon-ocr ทำงานพลาดเมื่อสั่งให้ตอบเป็น JSON ตรง ๆ

### line.py
ช่องทาง LINE Official Account ใช้บอทตัวเดียวกับหน้าเว็บ · `POST /api/line/webhook` ตรวจลายเซ็นจาก LINE → ตอบ 200 ทันที → ตอบลูกค้าเบื้องหลัง · แชต LINE ขึ้นในกล่องแชตหลังบ้านเหมือนแชตเว็บ · พนักงานตอบจากหลังบ้านแล้ว `push()` ส่งกลับไปที่ LINE · แสดงสถานะกำลังพิมพ์ระหว่างบอทคิด

### members.py
- `POST /api/members/signup` สมัครสมาชิกจากหน้าเว็บ: ตรวจชื่อ เบอร์ แพ็กเกจ โค้ดโปร และการยินยอม → ได้รหัสสมาชิกทันที สถานะ "รอยืนยัน" พร้อมยอดค้างชำระ · เบอร์ซ้ำกับสมาชิกเดิมจะขอให้ใช้เบอร์อื่น · จำกัด 5 ครั้งต่อชั่วโมงต่อ IP
- `POST /api/members/verify` ยืนยันตัวตนบนหน้าเว็บ ได้ข้อมูลสมาชิกที่ไม่มีเบอร์เต็ม

### conversations.py
API ของแชต แยกสิทธิ์ 2 ฝั่ง
- ลูกค้า: อ่านแชตของตัวเอง (ด้วยเลข ticket 10 ตัว) · บันทึกข้อความ · ขอคุยกับพนักงาน
- พนักงาน (ต้องล็อกอิน): ล็อกอิน · ดูทุกแชต · ตอบแทนบอท · เปลี่ยนสถานะ · ลบแชต

### backoffice.py
API ของหลังบ้าน (ต้องล็อกอิน) และข้อมูลร้านสำหรับหน้าเว็บ
- `GET /api/data` ข้อมูลร้านให้หน้าเว็บ (ไม่มีข้อมูลสมาชิก) · `GET /api/admin/data` ข้อมูลทั้งหมดให้หลังบ้าน
- รับสลิปจากแชตแล้วผูกเข้ากับยอดค้างของสมาชิก · พนักงานดูภาพสลิปได้ · ลบสลิปเก่าเกินกำหนดอัตโนมัติ
- เปลี่ยนสถานะการชำระ การจอง โปร และผู้สมัครใหม่ (ยืนยัน / ไม่อนุมัติ) · บอทใช้ค่าใหม่ทันที
- `dashboard()` ตัวเลขหน้าภาพรวมจากข้อมูลจริง · รีเซ็ตข้อมูลทดสอบกลับเป็นค่าตั้งต้น

### knowledge.py
API หน้าคลังความรู้ในหลังบ้าน: รายการเอกสารและสถานะดัชนี · ทดสอบค้น · อัปโหลดไฟล์ `.md` · สั่งสร้างดัชนีใหม่ · ส่งกราฟความรู้ให้หน้าแสดงกราฟ

### dbviewer.py
API ของหน้า `admin/dbviewer.html` · เปิดฐานข้อมูลแบบอ่านอย่างเดียว (`mode=ro`) แก้ข้อมูลไม่ได้ · แสดงทุกตารางพร้อมคำอธิบายคอลัมน์จาก `datadict.json` ที่เก็บในฐานข้อมูล และแถวข้อมูลทีละหน้า · ตรวจชื่อตารางกับรายชื่อจริงก่อนส่งเข้า SQL

### auth.py
ล็อกอินหลังบ้านแบบสาธิต: บัญชีเดียวจาก `config.py` (ค่าตั้งต้น admin / 1234) · token เก็บในหน่วยความจำ รีสตาร์ตแล้วต้องล็อกอินใหม่ · `require_admin` ใช้กั้นทุก API ของหลังบ้าน

### db.py
ฐานข้อมูล SQLite ไฟล์เดียวสำหรับทุกอย่าง
- แชตและข้อความ · ผู้ใช้ LINE · สลิปและภาพที่อัปโหลด
- ตารางข้อมูลร้าน 14 ตาราง (สมาชิก แพ็กเกจ การชำระ โปร ฯลฯ) สร้างจาก `data/db/*.json` ที่รากโปรเจกต์ด้วย `python -m app.db` (`build_dist.py` รันให้) · JSON ทั้งก้อนเก็บไว้ในตาราง `settings` ด้วย: คำพ้อง (`rag.py` อ่าน) คำอธิบายคอลัมน์ (`dbviewer.py` อ่าน) และข้อมูลร้านตั้งต้นสำหรับปุ่มรีเซ็ต · `x-fitness/` จึงไม่มีไฟล์ JSON
- ไฟล์เดียว `x-fitness/data/db/xfitness_db.sqlite3` อยู่ใน git และเซิร์ฟเวอร์อ่านเขียนไฟล์นี้ตรง ๆ ขึ้นเว็บแล้วพร้อมใช้ · ภาพสลิปอยู่ที่ `data/db/slips/` (ไม่อยู่ใน git)
- สร้างใหม่ทับไฟล์เดิมเมื่อรัน `build_dist.py` โดยเก็บของเดิมไว้ที่ `xfitness_db.backup.sqlite3` · ปุ่มรีเซ็ตข้อมูลทดสอบสร้างตารางร้านใหม่จากข้อมูลตั้งต้นใน `settings`
- `add_signup()` บันทึกผู้สมัครใหม่และยอดชำระแรกในรอบเดียวกัน กันรหัสสมาชิกซ้ำ

### limits.py
ขีดจำกัดที่ตรวจด้วยโค้ดก่อนเรียก AI ทุกครั้ง เก็บในหน่วยความจำ
1. จำนวนข้อความต่อนาที ต่อ IP (เว็บ) หรือต่อผู้ใช้ LINE · กันการยิงข้อความจนโควตา Typhoon หมด
2. การเดารหัสสมาชิก: นับครั้งที่เบอร์ผิดต่อรหัสสมาชิก ข้ามทุกแชต ผิดครบตามที่ตั้งไว้ รหัสนั้นถูกล็อกชั่วคราว
