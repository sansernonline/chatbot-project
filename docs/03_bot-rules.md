# X Fitness Chatbot — ข้อกำหนดต้องทำ / ห้ามทำ

> ผู้พัฒนา: 68076040 เบญจมาภรณ์ เจียนเกาะ · 68076065 สรรเสริญ มากเจริญ · ฉบับ 4 ต.ค. 2569 · ใช้คู่กับ `x-fitness/backend/app/prompts/system.md` และ `qa/1-questions.md`

บอท "เอ็กซ์" ตอบลูกค้าแทนร้าน X Fitness ทางหน้าเว็บและ LINE OA ข้อกำหนดแต่ละข้อมีรหัส (D = ต้องทำ, N = ห้ามทำ) ใช้ตรงกันทั้งในคำสั่งระบบ ตัวกันความเสี่ยง (guardrail) คำตอบของ API (ช่อง `rules`) และชุดทดสอบ

**บังคับด้วยอะไร** — ข้อที่เสียหายถ้าพลาดไม่ปล่อยให้ LLM ตัดสินเอง:

| ชั้น | ทำงานตอนไหน | ไฟล์ |
|---|---|---|
| จำกัดการใช้งาน | ก่อนทุกขั้น — ส่งถี่เกินตอบ 429 ไม่เรียก LLM · รหัสสมาชิกที่เดาผิดหลายครั้งถูกล็อก | `limits.py` |
| คำสั่งระบบ (prompt) | ทุกคำถาม — บอก LLM ว่าต้องทำ/ห้ามทำอะไร | `prompts/system.md` |
| guard ขาเข้า | ก่อนเรียก LLM — ข้อความเข้าข่าย ตอบข้อความตายตัว ไม่เรียก LLM | `guard.py` `INPUT_RULES` |
| กฎร้านที่โค้ดแนบ | คำถามเข้าข่าย → แนบข้อเท็จจริงของร้านไปกับคำถาม ไม่ขึ้นกับผลค้นคลังความรู้ | `business.py` `RULES` |
| ตรวจด้วยโค้ด | สลิป 5 ข้อ · ข้อมูลสมาชิกเฉพาะคนที่ยืนยันตัวตน | `business.py` |
| guard ขาออก | หลัง LLM ตอบ — แก้หรือแทนคำตอบที่ผิดกฎ | `guard.py` `check_output` |

| G-BANK | เลขบัญชีในคำตอบต้องเป็นบัญชีร้าน 123-4-54521-0 | แทนคำตอบด้วยข้อความปลอดภัย |
| G-URL | ที่อยู่เว็บ (https://… · www.… · ….com/.co.th) ในคำตอบต้องมีในคลังความรู้หรือข้อมูลที่ส่งให้ LLM | แทนคำตอบด้วยข้อความปลอดภัย + ปุ่มคุยกับพนักงาน |

## การป้องกันระดับระบบ

ไม่ผูกกับรหัส D/N แต่กันการใช้ระบบในทางผิด ค่าทั้งหมดปรับได้ใน `.env`

| ป้องกันอะไร | ทำอย่างไร | ค่าเริ่มต้น | ไฟล์ |
|---|---|---|---|
| ยิงข้อความรัว ๆ จนโควตา Typhoon หมด | จำกัดจำนวนข้อความต่อนาที ต่อ IP (Internet Protocol) ของหน้าเว็บ หรือต่อผู้ใช้ LINE · เกินแล้วตอบ 429 ไม่เรียก LLM | ข้อความ 30/นาที (`XF_RATE_LIMIT_PER_MIN`) · ภาพ 6/นาที (`XF_VISION_LIMIT_PER_MIN`) | `limits.py` |
| เปิดแชตใหม่เพื่อเดาเบอร์ 4 ตัวท้ายต่อ | นับครั้งที่ผิดต่อรหัสสมาชิก รวมทุกแชตและช่อง `member_id` ของ API · รหัสที่ถูกล็อกไม่ผ่านแม้ใส่เบอร์ถูก | ผิด 5 ครั้งใน 15 นาที ล็อก 15 นาที (`XF_VERIFY_MAX_FAILS` · `XF_VERIFY_LOCK_MIN`) | `limits.py` · `chat.py` |
| คำสั่งหลอกที่แบ่งส่งหลายข้อความ | ตรวจข้อความล่าสุดต่อกับ 2 ข้อความก่อนหน้าด้วยคำเฉพาะ (system prompt · ignore instructions · jailbreak · api key ฯลฯ) ไม่ใช้กฎ N-07 ทั้งชุด เพราะคำไทยต่อกันโดยบังเอิญได้ | — | `guard.py` `SPLIT_INJECTION` |
| เว็บอื่นเรียก API ของร้าน | CORS (Cross-Origin Resource Sharing) บน Render อนุญาตเฉพาะเว็บของร้าน · ในเครื่องเปิด `*` ให้หน้าเว็บที่เปิดจากไฟล์ใช้ได้ | `XF_CORS_ORIGINS` ใน `render.yaml` | `main.py` |
| ข้อความหรือภาพใหญ่เกิน | ข้อความไม่เกิน 500 ตัวอักษร · ภาพ JPG/PNG ไม่เกิน 5 MB | — | `chat.py` |
| คำขอปลอมเข้า LINE webhook | ตรวจลายเซ็น `X-Line-Signature` (HMAC-SHA256) | — | `line.py` |

ตัวนับเก็บในหน่วยความจำของเซิร์ฟเวอร์ 1 ตัว รีสตาร์ตแล้วเริ่มนับใหม่ ถ้าขยายเป็นหลายเครื่องต้องย้ายไปเก็บที่กลาง เช่น Redis

## การทดสอบ

```bash
cd x-fitness/backend
python -m eval.run --system --sample 100 --seed 1   # ทดสอบระบบรวม: สุ่มหมวดละ 100 ข้อจากคลัง (รวมข้อทดสอบกฎ)
```

ข้อความทดสอบและเกณฑ์ของแต่ละกฎ (รหัส D-xx · N-xx) อยู่ในคลังกลาง `qa/1-questions.md` ร่วมกับคำถามทดสอบ · ผลเขียนลง `qa/system/results/x-fitness-system-api-results.md`
